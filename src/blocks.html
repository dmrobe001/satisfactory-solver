What a block is

A factory here is a whole number of machines per recipe, every machine at 100 %. A block is a factory that cannot be split into two smaller ones that each obey the rules. Because machine counts cannot be negative, the set of blocks is finite and unique, and every valid factory of the pool's recipes is a sum of blocks (often in more than one way). Computed exactly with Normaliz (tools/blocks.py).

Open pools (the first four tabs): every fluid and every unusable item nets exactly 0 inside the block; raw resources are only drawn, in whole multiples of 30 per minute; usable items (anything the build gun uses, ammunition, filters, fuels, power shards) and power are free: a block may take them as inputs from other blocks or make them as outputs. So a block is a minimal module closed over its intermediates and fluids, joined to others by belts of usable items. Putting blocks together only needs every usable item's total to be 0 or more, since usable items may pile up. Every generator is included; power is shown, not limited.

Closed pools (the last two tabs, for comparison): usable items must net 0 or more inside each block, so blocks are self-sufficient chains from raw resources; most of them mix several products whose fractional machines complement each other.

Elementary modes (marked “mode”) are the blocks that are also extreme rays of the cone. Restricting the recipes never changes a block, it only removes blocks: each smaller pool's library is exactly the part of the bigger one that uses only its recipes. Pools: standard recipes (no hard-drive alternates; Compacted Coal, Polyester Fabric, Turbofuel and the Automated Miner count as standard), reachable from the listed raw resources without hand-gathered items.
